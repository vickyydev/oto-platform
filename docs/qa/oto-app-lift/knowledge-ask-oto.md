# SCRUM-461: Knowledge Base and Ask OTO scope

Knowledge Base article reads now use the signed-in tenant and the stored `ALL` or `SELECTED` branch scope. Staff can browse published articles assigned to their park job roles; managers and administrators can also work with drafts in their permitted branches. Detail and version reads, create, edit, publish, archive and delete enforce the same tenant and branch rules. An inaccessible ID returns 404. Article writes validate branch IDs in the tenant, and direct edits cannot change publication/version fields. The storage filter's obsolete `BRANCHES` comparison was corrected to `SELECTED`.

Knowledge-file list, detail, upload, metadata, re-index, delete, chunk and media routes now check tenant and branch access. Upload validates the branch and department before object storage receives the file; a failed database insert removes the uploaded object. Ask OTO searches only published articles and active indexed files visible to the user, filters chunks by those file IDs, and presents media from accessible active files. Keyword matching treats the question as text instead of a regular expression. The staff Browse control now calls the real published-article URL, and article HTML is sanitized before display.

Ask OTO thread and message routes now use the signed-in tenant and write the columns that exist in the app database; messages keep their source/checklist data in `content_json` and return the established response shape. Thread titles cannot be persisted because `otoapp.ask_oto_threads` has no title column; a supplied title receives 400 rather than being silently discarded. The additive migration need is recorded on SCRUM-193 for the platform lane.
