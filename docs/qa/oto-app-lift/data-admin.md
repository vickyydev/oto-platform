# SCRUM-193: Data admin access alignment

The live generic data editor remains at `/data` with its model index, schema view, record list, detail and create/edit screens. Its server API is guarded by `requireGlobalAdmin`, which accepts global admin and the original legacy admin role, but rejects operator admin. The client route gate previously allowed operator admin into all six data pages, where the API then refused every request. The route gate now matches the server rule.

The generic editor is a privileged maintenance tool. The vault access-item model was removed from its registry by SCRUM-463. SCRUM-466 also removed session, Xero OAuth token and reset-token models and stripped password hashes from user list/detail/write responses.

On 30 September, the documented administrator opened the live `/data` index. Reviewed staging screenshots `scrum-466-staging-model-index.png`, `scrum-466-staging-users-list.png` and `scrum-466-staging-user-detail.png` are attached to SCRUM-466 and parent SCRUM-193. Emails are masked. The Users table has no password-hash column and the detail renders PASSWORD as an empty value. A direct signed-in staging API check returned 200 for models, Users list and user detail; the removed Sessions, Xero Tokens and Auth Reset Tokens endpoints each returned 404. Neither user response contained a password field. SCRUM-466 is Deployed with the screenshots named in its Jira comment. Operator-admin role testing and a wider review of other maintenance models remain under SCRUM-193; the broader data editor is not yet verified for production data.
