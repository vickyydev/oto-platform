*What the Support page (Console, Watch, Support) can now find, and what it keeps hidden*
* *A band's trips through the gate.* Type the short code printed on a wristband (for example Z3-ENP9EH). The new "Gate events" section lists each passage at each park: when, entry or exit, which gate lane, which park, and why the gate said no when it refused (here ANTI_PASSBACK, "already inside"). The band's secret QR code is never shown, only the short code. A band with no passages shows "Nothing found".
* *A promotion voucher.* Type the voucher code as it appears on the slip, with its spaces (for example "Z3 XXXX XXXX X"). The "Promotion voucher" section shows its status, what it is worth, the park, and only the last four characters, never the whole code and never a staff name. Once used, it also shows where and when it was used and the receipt number (here Z3-000001). A code that does not exist shows "Nothing found" with the note that park promo codes are not searched here.
* *Searching never locks a till.* Ten made-up codes searched in the Console, then the real voucher redeemed straight away at a ZZ TEST till: the till took it the first time, with no lock and no warning, and the database recorded zero wrong-code attempts against the person or the till.
* *OTO App records by phone.* Type a phone number the way people say it (089 674 0001). The new "OTO App records" section lists what the OTO App holds for that number. It follows the OTO App's own rules: someone without permission to see personal details sees the names as "Masked"; a manager for one park sees only that park's records; an OTO App user who is not a manager gets the app's own answer ("Insufficient permissions") and nothing else.
* *Every search is recorded.* Activity shows one console.support.lookup row per search (15 searches by the admin, 15 rows), listing only what kind of thing was searched and which sections answered, never the value typed. An OTO App phone search also leaves its own sign-in row (auth.handoff_issue) for the hand-off into the OTO App.
