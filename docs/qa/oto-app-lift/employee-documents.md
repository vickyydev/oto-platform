# SCRUM-193: employee documents and spreadsheet preview

Employee document upload now writes directly to the configured object store and records its object path. Reading and deleting a document requires an authenticated user with access to the employee's branch, and the document must belong to that employee. The generic file route refuses this private folder. Legacy local document paths remain readable within the old employee-document directory in development. Excel preview parses its bounded upload in memory and leaves no temporary file.

The existing `employees.spec.ts` browser flow passed against the isolated full seed. It created an employee, uploaded a sample image, read the exact bytes through the employee route, received 404 from the generic route and a different employee path, deleted the document, and received 404 on a later read. A generated spreadsheet returned a preview without creating an employee. The first attempt timed out while the add page was loading; the rerun passed after the existing test's navigation wait was raised. A focused local MinIO check uploaded, read and deleted an employee document through the app's S3 adapter, then removed the disposable bucket. The production build passed; inherited app typecheck remained at 578 errors with no new diagnostic in the changed area, and changed-line ESLint found zero diagnostics. Staging review is pending.
