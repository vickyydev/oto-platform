## Confirmed findings — no fixes applied

1. **PAY-01 / medium / ownership and data integrity.** `POST /branches/:own/tax-overrides` accepts a category owned by another operator: native HTTP **200** and an actual persisted cross-owner pointer. The own-category control also returns 200. The route validates the branch, then inserts `categoryId/productId` without loading their ownership; the database FK proves existence only. No foreign value disclosure or mutation of the other operator's category was demonstrated. Proposed correction: load referenced records in the caller's transaction, require the proper owning operator/branch, return the same not-found refusal for foreign/missing references, and leave no row/audit success on refusal. Add native category and product parity/rollback controls before implementation.
2. **PAY-02 / medium / error contract.** A nonexistent category returns **500 `{error:{code:"INTERNAL",message:"Internal server error"}}`** from the foreign-key failure, with no override row. This is an input/reference problem. Proposed correction: the same bounded owner lookup should provide a clear 404 before INSERT; preserve sanitized unexpected-500 behavior. The foreign and absent cases were ordinary failing assertions, not `it.fails`, and both failures are retained.
3. **PAY-03 / low / stale contract text.** Catalogue DELETE's OpenAPI description and the older inventory say a used tender is refused. Current code and the passing native test archive a used tender after the manager's confirmation and preserve ledger tokens. Proposed correction: align wording/inventory with the already approved behavior; do not change archive semantics.

Category ownership was independently exercised. **Product-reference ownership is source-only, not runtime verified**: it uses the same direct-insert path, but this audit did not run a foreign/missing product case. It is a proposed regression requirement, not a third reproduced ownership finding.

Source-only observations are not promoted to additional defects: unsupported payment kill consumers, the missing tax-override UI/writer breadth and the environment-only gateway settings are explicit capability limits. Any proposal to add those controls needs a separate approved scope and the payment/prototype owner rules.
