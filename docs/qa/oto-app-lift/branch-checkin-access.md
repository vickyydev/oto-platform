# SCRUM-454: branch-scoped check-ins and QR links

The check-in board previously accepted authenticated requests across branches. SCRUM-454 is the tracked defect linked to SCRUM-193. The app-owned route guard now checks the branch of each check-in before any record read or mutation. The board list is limited to the kiosk's branch or the staff member's allowed branches; an explicit other-branch filter is refused. The manager QR token, QR image and available-nanny endpoints also require branch access. The existing `UserWithBranchAccess` import was corrected to its defining module.

An isolated local probe created synthetic staff and manager users limited to branch A, a branch-A kiosk session, and one check-in in each of two seeded branches. The staff list contained only branch A; branch-B list/read/status and six other record actions each returned 403, while own-branch read and status returned 200. The manager's branch-B QR token and QR image returned 403; own-branch endpoints returned 200. The kiosk's branch-B list/read/status returned 403 and own-branch list returned 200. The branch-B row stayed `registered`. All synthetic check-ins, accounts, sessions and kiosk device were removed, with database counts verified at zero.

A second local kiosk probe checked the available-nanny endpoint after the branch guard was added: other-branch access returned 403 and own-branch access returned 200; its device/session was removed. The final app production build passed. App typecheck fell from the inherited 578 errors to 577 after the import correction, with no diagnostic in the changed file. Scoped ESLint reported 37 inherited diagnostics and none on edited lines. Post-deploy staging checks and positive signed-in proof are pending. Deployed requires a named staging test-run attachment on SCRUM-454.
