**The decisions (final; build these, do not reopen them)**
- Drafts stay saveable. An administrator may save an incomplete station; what changes is that an incomplete station is **not ready for selling**, says so, and the till refuses to trade on it with a sentence naming what is missing.
- **Ready for selling** means, for a till-kind station: a valid code prefix; and for every tender the station routes to a terminal (card or QR at the EDC), an active terminal device assigned to that role on the station's box with a supported protocol. The protocol is chosen from a list (`ghl_linkpos`, `digio_tlv`, the simulated kind), never typed free; a saved terminal with a blank or unknown protocol is shown as unusable and refused when assigned to a routed tender.
- The API exposes readiness on the station view (`ready: boolean` and `reasons: string[]`, short sentences a receptionist understands: "No receipt prefix", "Card is routed to the terminal but no terminal is assigned", "The assigned terminal has no supported protocol"). The Console shows the reasons on the station card and in the drawer; the till's station picker shows a not-ready station greyed with its first reason and refuses to open it; the API refuses the station lease for selling on a not-ready station with the same sentence, so a hand-made request cannot bypass the screen. The sale-creation refusal in `sale.ts` stays as the last line of defence.
- Existing stations on staging that are incomplete become "not ready" at once; that is correct, not a regression. Do not write a migration; readiness is computed from what is already stored. If a terminal's protocol column needs a CHECK or an enum, keep it expand-only and state it in the ticket.
