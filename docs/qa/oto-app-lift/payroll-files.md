# SCRUM-193: payroll exports and payslips

Bank transfers, accounting journals, SSO filings, PIT filings and payslip PDFs now go to private object storage. Filenames include the payroll run ID; payslips also include the full employee ID. Export downloads require payroll-admin access to that run. Payslip downloads require either that run access or the employee's own account, plus a matching payroll summary. The generic file route refuses both private folders. Export format values are validated before a filename is built. Payslip files use a distinct download route so the existing payslip-record route does not treat a PDF filename as a database ID.

A focused local MinIO check generated all four CSV types and one payslip from the isolated full seed, read nonempty CSVs and `%PDF` bytes, then removed the files and disposable bucket. A local authenticated API check generated and downloaded a bank export and payslip (both 200), denied a staff account access to those files (403), and denied the generic object route (404). The first payslip download attempt found the pre-existing route collision (500); the distinct route passed on rerun. The live Exports screen also pointed at old routes: after its repair, a local browser downloaded all four CSVs successfully from a finalized seeded run. The generated local files were removed. The production build passed, changed-line ESLint had zero diagnostics, and app typecheck remained at its inherited 578 errors with no new payroll-area diagnostics. The seeded staff account had no payroll summaries, so a positive self-download is still open.

Commit `649735bf` is live on oto-app-staging as Render deployment `dep-dau3btdg1s2s73b9vge0`. Staging health returned 200, anonymous scoped payroll downloads returned 401, and generic payroll object paths returned 404. These checks do not prove a positive staging payroll export or payslip. Review also found that the older payslip-record route sends malformed IDs to PostgreSQL and returns 500; a small follow-up now rejects malformed IDs before querying, pending its own deployment.
