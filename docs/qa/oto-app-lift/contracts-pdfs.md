# SCRUM-193: contracts, letters and BEO PDFs

The OTO App's contract PDF path now renders bytes and stores finalized versions in the configured object store. Signed contracts and letters remain in their existing private folders. Their record routes check staff access before returning a five-minute object URL; the public signed-contract download requires an unexpired signed token. The old signed-PDF route requires staff sign-in and branch access. The generic file route cannot bypass these checks for contract, letter or BEO PDFs. Branch logos are embedded from stored images. BEO PDFs are rendered to object storage on S3 deployments; local development still streams them.

Local verification used an isolated full-seed database with the app's existing browser suites. `contracts.spec.ts`, `contract-version-conflict.spec.ts`, `contract-templates.spec.ts` and `beo-set-menu-refresh.spec.ts` passed (4/4). The contract flow additionally checked the finalized and signed downloads for real `%PDF` bytes. A focused BEO render produced a valid PDF. Finalized, signed-contract and signed-letter objects round-tripped through local MinIO using short-lived URLs; a wrong bucket was rejected and test objects were removed. Anonymous PDF routes refused access. The production build passed. The app typecheck's inherited baseline was 583 errors; this slice reports 578. Changed-line ESLint and staging checks are recorded separately when complete.

Local browser tests use the isolated development app with legacy sign-in enabled only for those tests. Staging uses platform sign-on. No credential or signing token was written to repository files.

The exact source commit `d7e0156c` is live on oto-app-staging as Render deployment `dep-dau2ne093c1s73cgcg40`. Staging `/api/status` returned 200; anonymous finalized/signed contract downloads returned 401, and the generic contracts, letters and BEO file paths returned 404. ## Branch-scope gate

The signed-in staging PDF walkthrough above proves the staff and object-store access paths for an administrator. It does not prove denial to a manager assigned to one branch within the same tenant. A separate local same-tenant, other-branch probe reproduced the BEO access gap before the branch-guard fix, and the patched helper passed 25 local checks across BEO setup, PDF, editor and timeline routes. A live restricted-manager refusal check remains pending after deployment. No staging account was created for this check: the platform's account-creation route would send a setup SMS through the configured provider, and the external staging database connection was unavailable. Do not describe the branch guard as staging-verified until a signed-in restricted-manager request to the other branch's BEO returns 404.
