# SCRUM-193: public parent RSVP staging check

On live `oto-app-staging` source `b20ed05b`, an existing launcher-signed administrator created one labelled synthetic birthday event (201) and its guest invitation token (200). Route review confirmed that event creation, token creation, and public RSVP submission write database rows only. The probe did not open the share controls, create message logs, or call any SMS, email, LINE, or WhatsApp sender.

An anonymous browser opened the public RSVP page at 820 × 1180. [parent-rsvp-form-tablet-2026-10-01.png](parent-rsvp-form-tablet-2026-10-01.png) shows the event and attendance choices. The browser submitted a synthetic attending response through the form; the signed-in event's RSVP entries endpoint returned exactly one matching row (200), and its summary returned one attending guest, one child, and one adult (200). On refresh, [parent-rsvp-confirmed-tablet-2026-10-01.png](parent-rsvp-confirmed-tablet-2026-10-01.png) showed the saved parent, child, and count details. Both images were visually reviewed: the invitation, form, and confirmation are readable without blocked controls at this viewport.

A random invalid invite returned 404 for both public read and RSVP write. [parent-rsvp-invalid-tablet-2026-10-01.png](parent-rsvp-invalid-tablet-2026-10-01.png) shows the public invalid-link state. Event deletion returned 204; a fresh authenticated event read and public read using its former invite both returned 404. The RSVP and invite rows are attached to the event with cascade deletion. No token value or guest identifier was recorded in this note or the screenshots. This verifies one positive parent RSVP and invalid-link refusal; it does not cover outbound invitation delivery or every language and edit variant.
