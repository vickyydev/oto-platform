## Findings

1. **The free-text AI fill still splits the lists when the chat says the adults eat the same** (step 6): two of two samples gave an Adults Menu of the same dishes in the adults' count, noted "Adults eat the same as the kids", and the editor then opens with the switch on. The catalogue review path behaves (one sample). The prompt change in `aiFill.ts` is advisory and the model did not follow it; a server-side fold (drop an adults' line that is the same dish as a kids' line, or the whole adults' list when every line says "the same") would make the outcome independent of the model.
2. **The park's catalogue was not read in two of the three Create BEO runs**, so those fills showed the free-text preview instead of the catalogue review (the route logs "the park's catalogue was not read for the AI fill" in that case). The api was mid-redeploy during the first run; the cause was not confirmed. Worth a look: the catalogue review is the path that reads the adults' menu right.
3. **The api on staging could not start from 04:54 to 12:25 Bangkok** (the voice-note provider set without its key; `assertProductionSafe` refuses to boot). Every api deploy in that window failed and the old instance kept serving; the proof's first till readings were of ba104804 and are kept as such (05, 06, 07) beside the re-check (05b, 06b, 07b).
4. Minor: the first run's driver process ended with the session cut, so its admin api session was never signed out through the route (its cookie is gone with the process; the re-check's sessions were all signed out and read back 401). The till's "Fully paid" header button shows on an unpaid party page (outside this ticket).
