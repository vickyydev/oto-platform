# Part 1. The BEO brief

## (a) The BEO editor today

Component: `client/src/components/beo/beo-event-editor.tsx`, function `BeoEventEditor` (4,539 lines). It opens as a right-hand sheet from the Events page (`client/src/pages/studio/events.tsx`, `Sheet` with `w-full sm:max-w-2xl`). Sections are an accordion where several can be open at once; Event Info is open on start.

**Top of the form.** The event title. A park picker (`select-event-branch`, only when the person sees more than one park; a badge otherwise). A "From the inbox" badge for events booked from a chat. A money badge from the till ("Paid", "No Deposit", "฿x Due", or "Additional bill open"; `tillFiguresOf`, `partyBillStateOf`, `openAdditionalBillsOf` in `shared/tillBilling.ts`). The date line ("12 November '26 at 14:00"). Buttons: **AI Fill** (paste a message), **Fetch from chat** (only for events booked from the inbox), **Print**, **Download PDF**. Under them a row of status marks: Info, Host, POS, Setup, Kitchen, Timeline (`getSectionStatus`).

The sections, in the order the code renders them:

1. **Event Info** (always). Typed: Title, Activities (free text), Decoration, Special Requests (multi-line), Child / Guest of Honor Name, Parent / Booking Name, WhatsApp Number (with a WhatsApp link), Kid Turning Age (number), Location (free text, for example "Party Room A"), Expected Kids, Expected Adults, Final Message to Parent ("staff only, not printed"). Picked: Date (date picker), Start Time and End Time. Each time shows a chip with a gear and a clear button; the gear opens a separate row with a time input and Confirm / Cancel. Studio events also get a Calendar Color picker.
2. **Party Host**. Picked: Assigned Party Host (search employees or roles, one), Entertainment Host (Optional, search employees, one; stored as the "backup" host). Then **Entertainment Acts**: "+ Add Act" adds a row with a typed act name, a time chip and a time input side by side, and a delete button. Each change is written at once (`addEntItemMutation`, `updateEntItemMutation`). No person and no instructions per act.
3. **Birthday Package** (birthday events only; `client/src/components/beo/beo-package-module.tsx`, `BeoPackageModule` with `section="package"`). Pick a package and Apply; Change Package, Re-apply when the template changed, Remove. A line of facts ("Up to 10 children · 4 adults included · Socks for all children · 3 hours · Weekday / weekend prices · Extra child · Extra adult", `packageFacts`). "Kitchen & bar slips at" (time). Package Breakdown and Add-ons: each item with Qty, Price, Billable switch and Notes, all editable. A **Package Total** worked out in the app (`PackageTotalBreakdown`, `partyPackageTotal`).
4. **POS**. Typed: POS Name. Line Items, each INCL or EXTRA with a description and an optional note, no price (`PackageLineItemRow`). Three tiles: Total from the till, **Deposit** (typed amount and a date picker), Outstanding from the till (`PartyDetailsTillTiles` in `beo-till-billing.tsx`). POS Notes (multi-line). A "Mark POS Done" task button in the header.
5. **Billing** (`BeoBillingSection` in `beo-till-billing.tsx`). The "From the till" panel (quote or sale lines, payments, additional bills, the older unassigned tab), the Deposit Request panel (sends the 2C2P QR into the chat and watches it), and "The app's own invoice rows" (`beo-billing-module.tsx`, `BeoBillingModule`: line items with unit prices including VAT, subtotal, VAT, totals, Outstanding, Deposit Paid with date, "Add to POS" checklist, Generate from BEO, Add from Templates).
6. **Setup Plan**. Ready by (time chip, gear, Confirm row). Who (type to search employees or departments, or type a free name). Tasks: "No setup tasks yet", then rows of typed tasks with an optional note and a bin; "Add Task". "General Setup Notes" in a fold. "Mark Setup Done" task button.
7. **Kitchen Plan**. "Not Needed" / "Needed" buttons. When needed: tabs **Kids Menu (n)** and **Adults Menu (n)** with one Service time per tab. Kids tab: a **Set Menu** switch; a Set Menu Template picker; the template's fixed items and choice groups with the parent's choices ("Selections received", "Awaiting parent"); resolved items editable; "+ Add item"; **Get Parent Link** and **Reset Selections**. Then "Additional Items": rows with a SET / EXTRA badge, minus, count, plus, an EXTRA price box, a typed name, a till-menu picker (`TillMenuPick`), the till code, a note button and a bin (`MenuLineItemRow`); "+ EXTRA" and "+ NEW ITEM (not in the menu)". Adults tab: the **Different for adults** switch; off shows the kids' list read-only; on gives the adults their own list with the same row controls. A line with the kitchen extras' total as the till will charge them (`BeoExtrasTotal`). Then **Cake**: No Cake / Our Cake / Own Cake, Qty 1 to 3, INCL / EXTRA, Cake Time (chip and Confirm row), a price box when EXTRA, cake notes. "Mark Kitchen Done" task button.
8. **Bar Plan**. One Service Time for the whole bar. Rows: SET / EXTRA badge, typed name, till drink picker, code, Qty, EXTRA price box, bin, a note line under it. "+ CUSTOM DISH", "+ SET", "+ EXTRA", and the bar extras' total.
9. **Timeline** (`beo-timeline-editor.tsx`, `BeoTimelineEditor`). Hand-made rows with a time and a label, plus the rows the server makes itself. Each row can be edited, ticked done or deleted.
10. **Parent Experience** (`beo-parent-experience-module.tsx`). Message language, WhatsApp confirmation, Kid Turning Age, Parent Portal link, Guest RSVP link and the RSVP counts.

**Bottom bar.** Archive (icon), Cancel, Save. Save sends one `PUT /api/events/:eventId/beo`; when a newly priced item may be billed on a settled party it first asks "Save the BEO and bill newly added priced items to this same party…" (`mayBillAtSave`).

**Dialogs.** AI Fill (paste text, Parse with AI, review, Load into Editor; `handleAiFillParse`, `handleAiFillApply`). The review in edit mode for Create BEO from the inbox (`beo-ai-review.tsx`, `BeoAiReviewDialog`: Event Info, Team, Package, POS, Setup Plan, Kitchen Plan, Entertainment, Not in the catalogue, Timeline, Deposit). Fetch from chat (`beo-fetch-from-chat.tsx`). New item not in the menu (`beo-party-menu-item.tsx`). Parent Menu Selection Link.

**On a phone** (read from the code, not driven): the sheet fills the screen; the two- and three-column grids fall to one column below the `sm` width; the header buttons wrap; each menu and bar row stays one line holding up to nine controls (badge, minus, count, plus, price box, name, till picker, code, note, bin), so rows are tight; the till tiles stay three across (`grid-cols-3`).

## M5: prices, VAT and the service charge

**What exists.** Each park has one tax row, `branch_tax_config` (`packages/db/src/schema/catalog.ts`), holding a config: the rates (VAT 7 %), a rule per taxable category (`tickets`, `fnb`, `bar`, `drop_off`, `parties`, `addons`, `merch`, `stored_value`; `TAXABLE_CATEGORIES` in `packages/shared/src/catalog-shapes.ts`) and where discounts sit. Each rule has a tax mode (none, inclusive, exclusive), a service charge percent and "tax on service charge". The seed sets VAT 7 % inclusive on every category except stored value, and service 0 (`packages/db/src/seed/index.ts`). So "the price is the final price, VAT inside" already works for tickets, packages, merchandise and F&B alike. Rules are per category, so a service charge for food only is already possible in the data: set it on `fnb` and on `bar` (a menu item is taxed `fnb` unless its category or the product says `bar`: `itemTaxCategory` in `packages/shared/src/item-cart.ts` and `apps/api/src/services/menu.ts`). A `tax_override` table (category or product) and a resolver exist (`resolveTax` in `apps/api/src/services/tax.ts`), but only the Console's catalog route reads it; the sale engine does not.

**What does not exist.** The engine, `computeTaxBreakdown` in `packages/shared/src/tax.ts`, always ADDS the service charge on top: "The service charge is ALWAYS additive; there is no mode in which it sits inside the quoted price." The file says why: the prototype has no such mode, and choosing its decomposition order would be inventing money. Switched on today at 8 % for F&B, a ฿200 dish costs ฿216, exactly what the operations lead was told.

**What "service charge included, F&B only" needs.** A new rule setting (service charge inside the price) in the shared config shape and the Console's tax editor; the engine unwinding 8 % and 7 % from the menu price instead of adding; one accounting decision: is VAT charged on the service charge (in Thai practice it usually is, giving net about ฿173.07, service ฿13.85, VAT ฿13.08 for ฿200), and how rounding falls so the total is exactly ฿200; new regression fixtures. Set on `fnb` and `bar` only.

**What would change on receipts and End of Day.** The guest pays the same ฿200, so End of Day's money by payment method and expected cash do not change (End of Day counts tenders and has no tax or service line: `apps/api/src/services/end-of-day.ts`). Each sale's stored split changes: `service_charge_satang` becomes non-zero and the net falls (`apps/api/src/services/sale.ts`, net equals gross less service less VAT), so the analytics reports' service column fills (`analytics-reports.ts`). The receipt would show "Service charge 8 % included" as an information row like "VAT included", instead of an added row (`packages/print/src/templates/receipt.ts`). Party bills, the BEO's extras hints (SCRUM-966, title above) and online F&B, where present, follow the same engine. A sale made before the change keeps its own snapshot.
