SCRUM-187 — S2-01b — Transactions, schema move and idempotency
Dev evidence 2026-09-20 on commit fe1ca67 (branch main, merged from feat/s2-01b-transactions-schema). 22 shared unit tests, 106 API integration tests (12 files, embedded Postgres per file), typecheck and lint clean.

Migrations run twice from empty, cleanly. pnpm --filter @oto/db verify-schema migrates a throwaway database twice and then compares the live catalogue with 0005_snapshot.json — tables, columns and their nullability, foreign-key names and their ON DELETE actions, indexes and their uniqueness, and check constraints — and fails if anything of ours is left in public. It reports: schemas analytics, booth, core, crm, drizzle, edge, pos, promo, public; public empty; everything matching. The drizzle schema is the migration journal's own; pgboss arrives with the job runner in S2-03 and is excluded from schemaFilter so a Drizzle diff never offers to drop it.

Numbering deviation: the plan calls the schema move 0003. S2-01a had already taken 0003 (the session lock model) and 0004 (the auth throttle), so it is 0005. Nothing else about it changed, and it is still the last migration allowed to break the previous release; CONTRIBUTING.md now carries the expand/contract policy from 0006.

The migration is hand-written, deliberately. drizzle-kit answers a schema move with DROP and CREATE, which would throw away the rows the move exists to keep, and for the five renames it asks table by table and refuses to guess without a TTY. So two scripts stand behind it: scripts/snapshot.ts writes the matching Drizzle snapshot without the prompts, and scripts/verify-schema.ts is the check above.

Schema placement. core holds tenancy, the fleet and the platform's own records (audit, idempotency, files, throttle); crm the customer (tier, member, child, visit); pos what the till sells and the money it takes. Two calls the plan left open are recorded in ARCHITECTURE.md 8.1: the catalogue sits in pos because a package, its holiday calendar and its tax rules are only ever read together and only by the till; tier sits in crm because a tier is what a person is, and the catalogue merely prices by it. promo, booth, analytics and edge are created empty for the tickets that fill them.

Renames while the tables are still empty: transaction to sale, transaction_line to sale_line, payment to payment_attempt, wristband to band, item to stock_item, with their columns, indexes and foreign-key constraint names moved too — Postgres does not rename a constraint when its table is renamed, and the snapshot tracks those names.

Constraint corrections: child to member is RESTRICT, so deleting a guardian cannot silently take a child's allergies with it; the wallet and sale ledgers lose CASCADE for the same reason; station carries its operator; role gains is_system and is unique per operator, with a partial unique index over the name where operator_id is null, because Postgres treats nulls as distinct and the plain index would have allowed two system roles called reception. All seven enumerations became text plus CHECK, not only the two the plan named: adding a value to a pg enum takes a DDL lock and cannot happen in a transaction that also reads the type. station_kind gains booth, contact_channel gains instagram.

Transactions. withTx(db, ctx, opName, fn) opens the transaction, the service writes its success audit row inside it with the tx handle, and the failure row is written after the rollback on the pool — the record of an attempt has to outlive the transaction that failed. Every mutating route is wrapped. transactions.test.ts forces the failure with a Postgres trigger that raises on the audit insert, inside the transaction and after everything the handler wrote, and asserts for POST /accounts, POST /visits and POST /public/bookings that the rows are gone, the success audit row is gone, and exactly one .failed row remains. A denial still leaves its own access.denied row, and the happy path still commits both.

Route guards. A route declares config: { permission, target } and a preHandler enforces it before the handler runs; scope targets are paths into the request, because the branch a caller acts on is in the URL and the guard has to know it first. Routes that are deliberately open, need only a session, are gated platform-wide, or resolve their permission from the request each say which. routes-guarded.test.ts walks the registry the plugin fills and fails if a route declares none of those — a new route with no config fails on the day it is written — and a second case pins the open surface, so widening it shows up in a diff.

Idempotency. The key is claimed in one statement (insert ... on conflict do nothing returning): two retries racing a dropped connection cannot both decide they are first, which is exactly what Sprint 1's read-then-write allowed. A duplicate arriving while the original runs gets 409 IDEMPOTENCY_IN_FLIGHT with Retry-After so the client polls the same key; a replay carries x-oto-replay; a 5xx releases the key so a genuine retry does the work rather than replaying a failure for a day; an expired key is taken over atomically. Two identical POST /members sent at once produce one member and one winner (test). Where a handler builds its response inside withTx it is stored in that same transaction; where it reads the response back after committing, the client-minted id covers the gap — POST /members and POST /visits accept a UUIDv7 and answer a repeat with the row that already exists, and the till now mints it.

Permission vocabulary and platform:sync. 28 strings became 99, grouped by the ticket that will enforce them, and the bundles nest: staff within reception within branch_manager within operator_admin. That nesting is not tidiness — the dominance rule refuses a grant of any role the caller does not fully hold, so a branch manager who could not grant reception could not staff their branch. The seed is re-runnable and is the platform:sync step: system roles and their permissions converge on every run and a permission removed from a bundle is withdrawn rather than left behind, while the demo rows are created once and left alone, so a password changed on staging survives a sync. platform-sync.test.ts proves a second run changes no row count across eighteen tables. pnpm db:platform-sync runs the platform half alone, which is what the deploy step will call.

Pool and process. Ten connections, a ten-second statement timeout, idle and connection timeouts, idle-in-transaction cut off at thirty seconds, an application_name in pg_stat_activity, and a pool error logged rather than fatal. SIGTERM drains rather than drops. Production refuses to boot on a development default — a localhost database, the oto:oto credentials, the demo MinIO keys, or a cookie that would travel in the clear — and reports every problem at once rather than one per restart.

QA (UI) step: GET /me/permissions for the seeded admin, viewed on the Login Users panel's permissions tab, now lists the Sprint 2 strings. That one is for the owner to run once S2-01c puts the POS on Render.
