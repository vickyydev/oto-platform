## Job 1: what is implemented

747's decision is to support the already accepted four- and six-character till
codes while keeping the existing invoice format. One-to-three-character station
segments, including T1, T2, PI1 and PI2, are unchanged byte for byte. Longer codes
use a deterministic three-character base-36 segment that excludes WEB. Different
codes can share a segment; the existing transactional, locked sequence counter
for the entire invoice stem and the global unique constraint prevent duplicate
invoice numbers. There is no new counter, setting, migration or truncation of a
saved till code. The invoice remains at most 20 characters.

746 now gives a typed value that parses as a printed band short code precedence
over voucher classification in the F&B form's submit capture. Explicit scanner
routes and the original voucher classifier remain unchanged. The actual page
path is `apps/pos/src/pages/OrderStation.tsx`, not the old components path quoted
in the request.

Implemented files:

- `packages/shared/test/s747-invoice-review.test.ts`: legacy byte pins, long-code
  format and stability, reserved WEB exclusion, limits and sequence overflow.
- `apps/api/test/s747-till-code-review.test.ts`: real four/six-character station
  saves and simulator QR attempts, same-action replay, deliberate long/long/short
  aliases with six concurrent requests and unique sequential invoice numbers.
- `apps/pos/src/lib/tillVoucher.ts`, the OrderStation page and
  `apps/pos/test/s746-typed-band-review.test.ts`: four-character typed bands,
